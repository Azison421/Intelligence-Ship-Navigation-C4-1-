# National_Test SAC V6 门控证据

日期：2026-08-06

## 固定契约

- checkpoint：`national-test-sac-checkpoint-v6`
- 观测：`local-waypoint-observation-v3`，166 维
- 动作：`five-calibrated-controls-v3`，5 个百分比唯一的前进控制
- 回放：`national-test-replay-v3`
- 状态：`national-test-self-training-state-v6`，强绑定地图与冻结走廊哈希
- 地图净空／激光急停：常规区 0.2 m／0.6 m；第 11→12 点哈希绑定狭窄区
  0 m／0.4 m，船体碰撞阈值不放宽

新训练从随机网络、空回放和指定 seed 开始，不读取任何 v37 权重或旧训练状态。

## 门控顺序

```text
100 局离线训练
  -> 20 局完整路线确定性评估（必须 20/20）
  -> 5 局 Unity 适应（允许更新）
  -> 5 局 Unity 验收（权重冻结，必须 5/5）
  -> PROMOTED
```

离线评估失败后进入下一 100 局块；累计 1000 个训练回合仍未达到 20/20 时明确进入
`TRAINING_GATE_FAILED`。Unity 验收失败数据进入 V3 回放，再返回离线训练；不会把
失败候选伪装为比赛默认模型。

active registry 在写入和读取时都校验 checkpoint 哈希、阶段及完整门控证据。缺少
20/20、5 局适应或 5/5 验收证据的 `PROMOTED` manifest 会直接被拒绝；历史上手工
标记的 68 局模型不再是活动模型。V6 状态与旧状态严格不兼容，不做迁移。

## 已完成的现场证据

- ROS 管理节点只订阅 `NavigationStatus` 控制，并发布只读 `DeviceStatus`。
- Windows 与 ROS 时钟约有 15.5 s 偏差；命令时间已改为使用设备反馈时钟，避免
  被管理节点的 2 s 新鲜度门拒绝。
- 10% 油门经 `NavigationStatus` 单通道到达设备回读，停止后持续归零。
- 双向标定日志：`forward-control-v2-20260805-173657.json`。
- 标定动作：`(10,-10)、(10,-5)、(40,0)、(10,5)、(10,10)`；两侧舵效均成立。
- V6 在第 400 个训练回合后完成正式 20/20 离线确定性评估；20 局均完成 13 点，
  零碰撞、零超时、零 `NO_SAFE_ACTION`。活动阶段已进入 `UNITY_ADAPT`。

## 离线环境修正

- 冻结地图和走廊在一个训练器生命周期内只编译一次。
- 出生扰动必须至少有一个通过同一 2 s 安全预测的动作。
- 走廊进度受当前比赛航点限制；航向使用可跨过航点的 1 m pure-pursuit 前视点，
  避免到达折点后才开始转向。
- 第 11 点锚点在 0.5 m 计分圆内按最大最小净空重新选择，删除不可执行的回头弯；
  离线雷达同步检测浮标圆形碰撞体，避免训练看不见 Unity 中的固定障碍。
- 安全零命令期间仍用已标定动力学传播惯性，不冻结船体位置。
- V3 物理量先做固定尺度归一化，再进入三个 GRU 头的 PyTorch `LayerNorm`，避免
  72 路量程和米制距离压没航向/横向误差信号；SAC 温度梯度按“熵高于目标则降低
  alpha”的方向更新。
- 第一个 100 局块使用完整走廊引导动作建立回放；actor 对安全掩码内的已执行动作做
  行为克隆预热，双 critic 同时按 SAC 回报学习。第 101 局起使用 DAgger 聚合当前
  策略访问状态：critic 仍只学习实际动作，actor 使用未加类别重权的专家标签；监督
  损失低于置信门后才逐步加入 SAC actor 项。聚合阶段沿用预热阶段的 Adam 学习率，
  每局最多 32 次更新；第 101 局起奇数局采集确定性完整路线，偶数局保留随机分段或
  随机完整路线。评估与 Unity 都不调用专家。
- 已位于当前目标圆的随机出生状态会重采样，禁止 0 步伪回合污染轮数和奖励。
- 航点、走廊、航向和横向误差以进度差分塑形；净空与姿态的逐周期项仅作小幅正则，
  不得累积到让长程完成局劣于早失败局。硬净空仍由安全 mask 强制执行。
- 回放只保留最近 64 个完整 episode，既不跨 episode 取序列，也不让 1000 局门控
  状态无界膨胀。
- 离线单局上限与 Unity 契约一致为 600 s；旧的 250 s 上限会把仍在正常前进的
  12→13 点轨迹误标为超时。
- 回合证据分别记录起始/结束航点和本局实际完成数；从中后段随机出生后到达终点不
  再等同于完整 13 点通过。
- Windows 状态读取先复制字节快照并立即释放文件句柄，原子替换对占用最多重试
  60 s；日常进度监控只读取小型 JSON/JSONL，不直接打开活动 PyTorch 状态。

## Unity 回合复位

每个计分的适应或验收回合结束后，控制器先持续发布零命令，再调用现有 Unity Reset
服务，并等待 `reset_status` 请求与完成确认。服务拒绝或 30 s 内没有完成确认时记录
`unity_reset_failed` 并停止门控，不会让撞墙后的船继续卡住收集伪回合。
非零油门下约 3 s 低速且位移不足 0.05 m 会先产生 `MOTION_STALLED` 安全截断，再进入
同一复位握手。

## 验证边界

当前活动训练结果以 `artifacts/logs/national_test_training_progress.json` 和严格状态
文件为准。本文件不把训练局中的偶然完成当作 20/20，也不把离线门通过当作 Unity
5/5。当前离线门已通过，但未完成 5 局适应和最后 5/5 前，不得宣称存在比赛默认模型。
